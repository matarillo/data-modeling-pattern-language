# 業務データモデリングのパターンランゲージ

事実・イベント・状態遷移を中心とする設計手法の比較と統合

事実・イベント・状態遷移を中心に、業務データの複数の設計手法を比較し、組み合わせて使う方法を説明します。在庫・受注・出荷・請求・入金を題材に、通常のRDBMSで整合性を保つ設計を扱います。全体像は次の3文書で構成します。

- [簡潔版](docs/report-concise.md)：設計の要点を短く説明します。
- [詳細版](docs/report-detailed.md)：パターン、設計判断、実証を詳しく説明します。
- [業務モデル](docs/business-model.md)：全属性ER図、表の責務、CRUDと原子性を参照できます。

## 検証範囲

付属のPostgreSQL検証は、固定された単一SKUのテストフィクスチャ上で、V01〜V04の4ケース、合計108アサーションを記録しています。基本フローと派生データの再構築、過剰引当の防止、冪等な再送と二重入金の防止、出荷と取消の競合を確認します。性能、本番環境の権限、一般的な複数SKU運用、完全な二時制、UIの動作を評価するものではありません。

同梱の`results.json`は記録済みの実行結果です。再実行は新しい実行結果を生成し、公開チェックアウト内の結果ファイルを更新します。既存結果を保持したい場合は、公開チェックアウトの使い捨てコピーで実行してください。再実行手順と環境条件は[検証ガイド](validation/README.md)を参照してください。
